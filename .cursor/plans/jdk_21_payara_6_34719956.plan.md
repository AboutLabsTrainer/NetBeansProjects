# JDK 21, Payara 6, passende Jakarta-EE-Version

Zielstack auf diesem Rechner, nur in den genannten Kursordnern (`Java SE`, `Java OO`, `Java Anwendungsentwicklung`, `Java Web Basic`, `Java Web Aufbau`, `Spring Boot Basic`, `Spring Boot AK`). `Tmp`, `Rheinwerk` und `Teilnehmerprojekte` bleiben unangetastet.

## Installierte Versionen

- JDK zum Kompilieren und als Server-JVM: **21.0.11** unter `C:\Program Files\Java\jdk-21.0.11`. JDK 25.0.1 bleibt installiert; `JAVA_HOME` und die NetBeans-IDE-JVM (`netbeans_jdkhome` in Apache NetBeans 31) zeigen weiter auf JDK 25. Projekte kompilieren trotzdem mit Release 21.
- Server: **Payara Community 6.2025.10** unter `C:\payara6`. Enthaltenes EclipseLink: **4.0.7.payara-p1**, Import `jakarta.persistence` `[3.1,4)`. Payara 7.2026.9 unter `C:\payara7` (EclipseLink 5.0.0, Jakarta EE 11) wird nicht mehr der Kurs-Server.
- Dazu passende API, nicht das alte Java EE 8 (`javax.*`) und nicht Jakarta EE 11:
  - `jakarta.jakartaee-web-api` **10.0.0**, Scope `provided`
  - Servlet 6.0 (`web-app_6_0.xsd`), Persistence **3.1** (`persistence_3_1.xsd`), Faces 4.0, CDI 4.0 (`beans_4_0.xsd`)
- IDEs:
  - **Apache NetBeans 31**, Userdir `%APPDATA%\NetBeans\31`. Plattformname `JDK_21` zeigt schon auf jdk-21.0.11. Der Deployer-Token `pfv5ee8` ist der interne Name des Payara-Plugins in dieser Installation, kein Payara 5. Die einzige registrierte Instanz zeigt aktuell auf `C:\payara7`.
  - **IntelliJ IDEA 2026.2.3** (Build 262.10968.63). SDK-Name in `jdk.table.xml` ist exakt `21`. Payara Tools **2.9.1** ist installiert, es ist aber kein Payara-Server eingetragen.
  - **VS Code 1.142.0** mit Extension Pack for Java 0.31.2, Language Support for Java **1.57.0** und Community Server Connector 0.26.22. Die Workspace-Datei [.vscode/settings.json](.vscode/settings.json) setzt `java.configuration.runtimes` schon mit Default **JavaSE-21** auf jdk-21.0.11. `java.jdt.ls.java.home` bleibt **JDK 25**: Version 1.57 startet den Sprachserver nur auf JDK 25+. `spring-boot.ls.java.home` und `rsp-ui.rsp.java.home` zeigen bereits auf jdk-21.0.11.

## Java Web

EclipseLink nicht ins WAR legen. Provider in `persistence.xml` bleibt `org.eclipse.persistence.jpa.PersistenceProvider`; die Laufzeit ist das EclipseLink 4.0.7 des Servers.

Anpassen:

- [Java Web Aufbau/Tag07-jpa-jdbc](Java%20Web%20Aufbau/Tag07-jpa-jdbc), [Tag08-manytoone](Java%20Web%20Aufbau/Tag08-manytoone), [Tag09-jpa-relations](Java%20Web%20Aufbau/Tag09-jpa-relations), [Tag10-jsf](Java%20Web%20Aufbau/Tag10-jsf): `jakarta.ee.version` von **11.0.0** auf **10.0.0**, Persistence-Schema von **3.2** auf **3.1**. Kommentare und READMEs, die Payara 7 / Jakarta EE 11 nennen, auf Payara 6 / Jakarta EE 10 ändern.
- Übrige Web-Module, die noch `source/target` oder `release` **17** haben (Basic Tag01, 03–08; Aufbau Tag01, 03–05), auf **21** setzen, inklusive fest verdrahtetem `<release>17</release>` im Compiler-Plugin. Servlet-API 6.0.0 und EE-10-API 10.0.0 bleiben.
- [Java Web Basic/Tag10-jdbc](Java%20Web%20Basic/Tag10-jdbc): `web-app_5_0.xsd` auf `web-app_6_0.xsd`.
- [Java Web Basic/Tag09-pools](Java%20Web%20Basic/Tag09-pools): Compiler-Plugin steht auf **source/target 11** (Plugin 3.8.1), nicht nur die Properties. Beides auf 21. Persistence **3.0** (leere Unit ohne Provider) auf **3.1** mit `org.eclipse.persistence.jpa.PersistenceProvider`.
- [Java Web Aufbau/Tag02-listeners](Java%20Web%20Aufbau/Tag02-listeners): Cargo-`containerId` `glassfish5x` auf `glassfish7x` (Cargo-Name für Payara 6).
- In jedem Web-`nb-configuration.xml`: `netbeans.hint.jdkPlatform` = `JDK_21`, `j2eeVersion` = `10-web`. Deploy-Server-Hint bleibt `pfv5ee8`.

## JDK 21 in SE, OO, Anwendungsentwicklung, Spring Boot

- Ant-Projekte (`nbproject/project.properties`): `javac.source` und `javac.target` auf **21**, `platform.active` auf **JDK_21** (heute teils 1.8, 11, 17, 24 oder 25). Betrifft `Java OO` (alle 5 Übungen), `Java SE` Grundlagen und Erweiterte Techniken, sowie die Ant-Projekte in `Java Anwendungsentwicklung` (Tag01, Tag02, ContactEditor).
- Dieselben Stufen stehen teils fest in `build.xml` und gelten dann vor den Properties: [Tag05-functions](Java%20SE/Java%20Erweiterte%20Techniken/Tag05-functions/build.xml) (`source="1.8"`, `project.properties` unvollständig), [Tag06-streams](Java%20SE/Java%20Erweiterte%20Techniken/Tag06-streams/build.xml) (`source="8"`), [Tag08-threads](Java%20SE/Java%20Erweiterte%20Techniken/Tag08-threads/build.xml) und [Tag09-sync](Java%20SE/Java%20Erweiterte%20Techniken/Tag09-sync/build.xml) (`source="17"`). Diese Attribute auf 21 setzen. Das Ant-`build.xml` unter [programs-on-the-island](Java%20SE/Java%20ist%20auch%20eine%20Insel/programs-on-the-island) hat ein nacktes `<javac>` ohne Release; dort 21 ergänzen. Die Maven-POMs der Insel bleiben bei 21. `hibernate-validator` ist Bean Validation, kein JPA-Provider, und bleibt.
- Eclipse-`.classpath` (von VS Code gelesen, gitignoriert): `JavaSE-25` und `JavaSE-1.8` auf `JavaSE-21`. Das betrifft OO, Grundlagen, AE-Ant-Projekte, ET Tag04 und Tag06. Einträge, die schon `JavaSE-21` sind, bleiben.
- Maven: `Java Anwendungsentwicklung` Tag04-swing und Tag05-javafx von 17 auf 21 (JavaFX-Artefakte sind schon 21). Tag08–10 bleiben bei JDK 21, EclipseLink **5.0.0** und Persistence **3.2** (`RESOURCE_LOCAL`, kein Payara).
- Spring Boot: kein Payara, kein EclipseLink. Hibernate nur über `spring-boot-starter-data-jpa`, Version nicht anpinnen. Einzige JDK-Abweichung: [Spring Boot AK/05-caching](Spring%20Boot%20AK/05-caching) `java.version` **17** auf **21**. Die unterschiedlichen Boot-Versionen (3.2.x–3.5.16) bleiben; die JPA-Module sind schon auf 3.5.16.
- [README.md](README.md) an den neuen Stack anpassen (heute steht dort Payara 7.2026.8 / EE 11 / EclipseLink 5 für die Web-JPA-Tage).

## IDE-Konfiguration auf diesem Rechner

- NetBeans 31: die registrierte Instanz von `C:\payara7` auf `C:\payara6` umbiegen (`Instances\.nbattrs`, `PayaraEE6\Properties`, `payara\common.properties`, `javaee\project.properties`). Server-JVM bleibt `C:\Program Files\Java\jdk-21.0.11`. Die IDE selbst weiter mit JDK 25 starten.
- IntelliJ 2026.2.3: vorhandene, gitignorierte `misc.xml` von `languageLevel="JDK_25"` und `project-jdk-name="25"` auf **JDK_21** und SDK-Name **`21`** stellen. Betrifft die Ordner `Java Anwendungsentwicklung`, `Java OO`, `Java SE/Java Grundlagen`, `Java SE/Java Erweiterte Techniken`, `Java Web Basic`, `Java Web Aufbau` und `Spring Boot Basic`. `Java SE/Java ist auch eine Insel` ist schon JDK 21; dort nur die veralteten Targets in `compiler.xml` (11 und 17) auf 21 setzen. Payara Tools 2.9.1 bekommt den Server `C:\payara6` mit JDK 21.0.11.
- VS Code: Workspace-Runtimes nicht umbauen. `java.jdt.ls.java.home` bleibt JDK 25, Default-Runtime bleibt JavaSE-21. Community Server Connector auf `C:\payara6` zeigen. `.vscode` und `.idea` bleiben gitignoriert.
